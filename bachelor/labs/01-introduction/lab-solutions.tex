\begin{solutionbox}{Step 1 -- Model IT / OT / IIoT calls}
\textbf{Decision rule to apply when grading:} \emph{IT} = handles data,
no physical actuation; \emph{OT} = controls a physical process, often
with safety/availability priority; \emph{IIoT} = network-connected
device that bridges both (telemetry or remote control over IP).
\begin{itemize}\setlength{\itemsep}{1pt}
  \item \textbf{Projector / Wi-Fi AP -- IT.} Pure information assets; CIA priority C > I > A.
  \item \textbf{Elevator, HVAC, fire panel -- OT.} Real-time control of a physical process; priority A > I > C; safety-relevant.
  \item \textbf{Badge reader, smart meter, telemetry vending -- IIoT.} OT-style function (door release, metering) reachable over IP; both attack surfaces apply.
\end{itemize}
A defensible alternative classification with sound reasoning earns
full marks -- this is a discussion lab, not a quiz.
\end{solutionbox}

\begin{solutionbox}{Step 2 -- Stakeholder map (example: elevator)}
Expected nodes and the CIA priority each stakeholder pushes:
\emph{Operator} (building manager) -- \textbf{Availability};
\emph{Owner} (university) -- \textbf{Availability + Integrity} (liability);
\emph{Integrator} (lift service company) -- \textbf{Integrity} (safe firmware, signed updates);
\emph{Vendor / OEM} -- \textbf{Integrity + Confidentiality} (IP protection);
\emph{Regulator} (TUV / national lift inspectorate) -- \textbf{Safety \& Integrity} via certified configuration.
Award the point if the diagram shows at least four of these five roles with at least one CIA label per role.
\end{solutionbox}

\begin{solutionbox}{Step 3 -- Reflection, model answer}
Expected line of argument: the \emph{operator} (or facility manager)
will push back hardest against a control that interrupts normal
operation -- e.g.\ a forced reboot for patching, an MFA prompt on an
HMI, or a network segmentation that blocks a vendor's remote-support
tunnel. This is \emph{legitimate} because their KPI is uptime and
safety of the running process; an unplanned stop on an elevator,
boiler or production line can cause injury, regulatory breach, or
six-figure losses far exceeding the residual cyber risk the control
was meant to mitigate. Good answers note that the fix is not to
overrule the operator but to schedule the control inside a maintenance
window and to involve the integrator/vendor early.
\end{solutionbox}

\begin{solutionbox}{Discussion points to surface}
\begin{itemize}\setlength{\itemsep}{1pt}
  \item CIA triad inverts between IT (C-I-A) and OT (A-I-C).
  \item ``Smart'' anything is usually IIoT -- so the attack surface is doubled, not halved.
  \item Ownership is rarely the same as operation: vendor remote access is the recurring blind spot.
  \item Safety regulator > security policy when the two collide (fire panel, lift).
\end{itemize}
\end{solutionbox}
