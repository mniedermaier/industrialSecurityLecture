\labheader

\begin{goalbox}
Show that a passive ICS-aware IDS can detect the Modbus injection from Lab 02 without ever sending a packet itself.
\end{goalbox}

\begin{stepbox}{1 -- Stack and baseline traffic}
The Zeek container is already up and sniffing on the lab subnet. Generate baseline traffic:
\begin{lstlisting}[language=bash]
docker compose exec student python3 /labs/scripts/modbus_poll_loop.py &
POLL=$!
sleep 60
kill $POLL
\end{lstlisting}
Inspect host-side logs:
\begin{lstlisting}[language=bash]
ls bachelor/labs/zeek-logs/
tail bachelor/labs/zeek-logs/modbus.log
\end{lstlisting}
\end{stepbox}

\begin{stepbox}{2 -- Trigger the injection}
\begin{lstlisting}[language=bash]
docker compose exec student python3 /labs/scripts/modbus_inject.py
\end{lstlisting}
Within seconds, a notice should land in \texttt{notice.log} tagged \texttt{ModbusWatch::Unsolicited\_Write}.
\end{stepbox}

\begin{stepbox}{3 -- Tune one false positive}
Edit \texttt{bachelor/labs/zeek/local.zeek} so writes from the student container (172.28.0.20) are not treated as notices (assume the engineering WS is sanctioned). Restart:
\begin{lstlisting}[language=bash]
docker compose restart zeek
\end{lstlisting}
Re-run the injection -- the notice should now be suppressed.
\end{stepbox}

\begin{deliverbox}
Hand in: \texttt{notice.log} excerpts before and after tuning, your modified \texttt{local.zeek}, and a 5-line answer to: ``\emph{Who would receive this alert in a real SOC, and what is their first action?}''
\end{deliverbox}
